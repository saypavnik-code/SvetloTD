# Opening and economy proposals (generated)

Generated by `npm run report:balance -- --write` from the headless simulation. Do not edit by hand:
`tests/balance.test.mjs` fails when this file is stale. **Nothing here changes game data.** A candidate is a temporary
scenario; the owner picks one (or asks for another) and a later patch writes the numbers into the data files.
Browser smoke: not run.

## Method, metric and limits

- Same simulation as `docs/ECONOMY_REPORT.md` (real code, 30 Hz, deterministic), difficulty normal, the four catalogued
  tower builds. Two hero modes: `idle` (parked on the base, auto-attack only) and `skills` (also casts Q when two or more
  enemies are inside its blast radius, W when a tower is inside its radius). Hero movement and the watchtower are not simulated.
- **Acceptance:** the best build still has at least 3 lives when wave 11 starts, i.e. it held waves 1-10. It is a bar for
  the opening only; it says nothing about waves 11-40.
- `cleared` counts waves that ended (leaks allowed). `lives@11` is the lives left when wave 11 starts (0 if defeated earlier).
- Results depend on the four build rule lists in `tests/support/simulate.mjs`; a smarter player does better by an unmeasured amount.

## Decisions the owner has to make

1. **Opening.** Pick candidate A, B or C, or name other numbers. A and C change `src/data/waves.ts`; B and C change
   `startingGold` in `src/config/difficulty.ts` and `bounty` in `src/data/enemies.ts`. Whatever is picked, waves 11+ stay
   unsolved (see "best build over 40 waves"): they need their own measurement and a later sprint.
2. **Difficulty bonus.** `max(formula, bonusGold)` makes `waveBonusBase/Scale` dead. Options: (a) delete the two fields: the bonus becomes
   `bonusGold` on every difficulty (5730 gold over 40 waves; change against today: -1 / 0 / 0 gold on normal / hard / insane); (b) replace the
   rule with `round(bonusGold x multiplier)` using 1.0 / 0.8 / 0.6 for normal / hard / insane (5730 / 4584 / 3438 gold).
3. **Lumber.** It is earned and never spent. Options: (a) remove it from the HUD and the systems; (b) add the sink that the
   `LumberManager` header comment describes (mercenaries and tier-3 towers), which needs new content and is a larger sprint.
4. **Calibration.** The skill rule is fixed and the hero never moves. One human play of waves 1-3 with skills (lives lost per wave)
   tells how pessimistic `idle` and `skills` are before any number is written into the data.
